# راه‌اندازی «انبار» روی سرور

این راهنما برای یک سرور لینوکس در ایران با Docker است. نرم‌افزار و Caddy (برای HTTPS خودکار) با یک فایل `docker-compose.yml` بالا می‌آیند.

## ۱. چه چیزهایی لازم است
- سرور لینوکس (اوبونتو ۲۲ یا ۲۴ پیشنهاد می‌شود)، دست‌کم ۲ هسته، ۲ گیگ رم و ۲۰ گیگ دیسک.
- Docker و Docker Compose نصب‌شده (`docker compose version` باید جواب بدهد).
- یک دامنه یا زیردامنه، مثلاً `anbar.sandeloos.com`، با رکورد **A** که به IP سرور اشاره کند.
- پورت‌های ۸۰ و ۴۴۳ سرور از اینترنت باز باشد (برای گواهی HTTPS و دسترسی کاربران).

## ۲. آوردن نرم‌افزار روی سرور
```bash
git clone https://github.com/Sandeloos/anbar-kala.git anbar
cd anbar
cp .env.example .env
```
فایل `.env` را باز کنید و پر کنید:
- `DOMAIN`: همان دامنه، بدون `https://`
- `APP_SECRET`: یک رشته‌ی تصادفی بلند. با این دستور بسازید و **جای امنی نگه دارید** (کلیدهای ووکامرس با آن رمز می‌شوند؛ بدون آن نسخه‌ی پشتیبان کلیدها را باز نمی‌کند؛ هیچ‌وقت عوضش نکنید):
  ```bash
  openssl rand -base64 48
  ```
- `MANAGER_USERNAME` و `MANAGER_PASSWORD`: مدیر اول (فقط در اولین اجرا ساخته می‌شود).

## ۳. ساختن و اجرا
```bash
docker compose up -d --build
```
بعد از یکی دو دقیقه `https://دامنه` را باز کنید و با نام کاربری و رمز مدیر وارد شوید.

وضعیت و گزارش‌ها:
```bash
docker compose ps
```
```bash
docker compose logs -f anbar
```

### اگر سرور به Docker Hub یا npm دسترسی ندارد
در بعضی سرورهای ایران دانلود از Docker Hub یا npm بسته است. دو راه:

**راه ۱ — آینه‌ی Docker:** در `/etc/docker/daemon.json` یک آینه‌ی داخلی (مثلاً آینه‌ی ابرآروان یا دیگر آینه‌های داخلی) بگذارید (آدرس دقیق آینه را از سرویس‌دهنده‌ی سرورتان بپرسید) و Docker را دوباره راه بیندازید:
```json
{ "registry-mirrors": ["https://docker.arvancloud.ir"] }
```
```bash
sudo systemctl restart docker
```
برای npm هم می‌شود هنگام ساخت از آینه استفاده کرد (اگر در دسترس است).

**راه ۲ — ایمیج آماده از GitHub:** هر بار که کد در GitHub به‌روز می‌شود، بخش Actions یک فایل `anbar-image` می‌سازد. از صفحه‌ی آخرین اجرای CI دانلودش کنید، روی سرور بگذارید و:
```bash
gunzip -c anbar-image.tar.gz | docker load
```
```bash
docker compose up -d
```
(در این حالت `--build` نزنید.) ایمیج Caddy را هم اگر لازم شد به همین شکل از جای دیگری بیاورید و در `.env` با `CADDY_IMAGE` نامش را بدهید.

## ۴. HTTPS
Caddy گواهی Let's Encrypt را خودش می‌گیرد و تمدید می‌کند. اگر گرفتن گواهی از سرور ایران مشکل داشت (در `docker compose logs caddy` دیده می‌شود):
- دامنه را پشت CDN داخلی (مثلاً ابرآروان) با گواهی خود CDN بگذارید و در `Caddyfile` به‌جای `{$DOMAIN}` بنویسید `http://{$DOMAIN}` تا Caddy فقط HTTP بدهد و CDN رمزگذاری کند.
- یا گواهی خودتان را در Caddy تعریف کنید (`tls /path/cert.pem /path/key.pem`).

اگر فقط برای آزمایش اول بدون HTTPS بالا می‌آورید، در `.env` بگذارید `COOKIE_SECURE=0` (و بعد حتماً به ۱ برگردانید)، وگرنه ورود کار نمی‌کند.

## ۵. وصل کردن سایت شرکت‌ها
- در نرم‌افزار: شرکت‌ها ← شرکت جدید ← آدرس سایت و کلید API ووکامرس (دسترسی «خواندن»).
- سرور «انبار» باید بتواند به سایت شرکت‌ها وصل شود. اگر افزونه‌ی امنیتی سایت (مثل Wordfence یا فایروال هاست) درخواست‌ها را می‌بندد، IP سرور انبار را در آن مجاز کنید.
- افزونه‌ی «اتصال انبار» را از صفحه‌ی شرکت دانلود و روی وردپرس نصب کنید؛ آدرس دریافت با دامنه‌ی شما ساخته می‌شود و سایت باید بتواند به آن وصل شود.

## ۶. پشتیبان‌گیری
- هر شب (ساعت ۲ تا ۵ به وقت تهران) یک نسخه‌ی کامل دیتابیس در volume با نام `anbar-data` و پوشه‌ی `backups` ساخته می‌شود؛ تعدادش در «تنظیمات» قابل تغییر است (پیش‌فرض ۱۴).
- از «تنظیمات ← سیستم و پشتیبان» هم می‌شود همان لحظه نسخه گرفت و دانلودش کرد. **نسخه‌ها را جای دیگری هم نگه دارید** (مثلاً هر هفته دانلود کنید).
- `APP_SECRET` را کنار نسخه‌ها (ولی جدا و امن) نگه دارید.
- هر نسخه بلافاصله بعد از ساخته شدن باز و با بررسی خود SQLite آزموده می‌شود؛ نسخه‌ی خراب (مثلاً به‌خاطر پر بودن دیسک) نگه داشته نمی‌شود، نسخه‌های قبلی سالم پاک نمی‌شوند و خطا در لاگ ثبت می‌شود.

### بازگرداندن یک نسخه
```bash
docker compose stop anbar
```
```bash
docker run --rm -v anbar_anbar-data:/data -v "$PWD":/backup alpine sh -c "cp /backup/anbar-YYYYMMDD-HHMMSS.db /data/anbar.db && rm -f /data/anbar.db-wal /data/anbar.db-shm"
```
```bash
docker compose start anbar
```
(نام volume را با `docker volume ls` ببینید؛ معمولاً `anbar_anbar-data` است. فایل نسخه را قبلش در همان پوشه‌ای بگذارید که دستور را اجرا می‌کنید.)

## ۷. به‌روزرسانی
```bash
git pull
```
```bash
docker compose up -d --build
```
تغییرات دیتابیس خودکار اعمال می‌شود. قبل از هر به‌روزرسانی از «تنظیمات» یک نسخه‌ی پشتیبان بگیرید.
هنگام به‌روزرسانی، سرور قدیم اول همگام‌سازی در حال اجرا و درخواست‌های نیمه‌کاره را تمام می‌کند (حداکثر ۴۰ ثانیه) و بعد خاموش می‌شود؛ مرورگرها خودشان دوباره وصل می‌شوند و اگر ثبتی وسط کار بود، همان درخواست بدون تکرار دوباره فرستاده می‌شود.

## ۷٫۱. پایش (اختیاری)
- `https://DOMAIN/health` یعنی سرور روشن است؛ `https://DOMAIN/ready` یعنی آماده‌ی کار است (دیتابیس در دسترس است). Docker همین را هر ۳۰ ثانیه بررسی می‌کند (`docker compose ps` ستون STATUS).
- برای Prometheus/Grafana در `.env` مقدار `METRICS_TOKEN` را بگذارید (`openssl rand -hex 24`) و `https://DOMAIN/metrics` را با سرآیند `Authorization: Bearer <token>` بخوانید. بدون آن، این آدرس خاموش است.
- هر درخواست یک شناسه دارد (`X-Request-Id`) که در لاگ Caddy و لاگ انبار یکی است: `docker compose logs anbar | grep <id>`.
- «تنظیمات ← سلامت داده‌ها» نتیجه‌ی بررسی شبانه را نشان می‌دهد؛ اگر قرمز بود، قبل از هر کاری یک نسخه‌ی پشتیبان بگیرید و گزارش را بفرستید.

## ۸. اگر چیزی کار نکرد
| نشانه | چه کنید |
|---|---|
| صفحه باز نمی‌شود | `docker compose ps` و `docker compose logs caddy`؛ رکورد DNS و باز بودن پورت ۸۰/۴۴۳ را بررسی کنید |
| ورود انجام نمی‌شود ولی خطا هم نمی‌دهد | سایت با HTTPS باز نشده؛ HTTPS را درست کنید (یا موقتاً `COOKIE_SECURE=0`) |
| «اتصال به سایت برقرار نشد» در صفحه‌ی شرکت | سرور به سایت شرکت دسترسی ندارد یا فایروال سایت IP را بسته |
| افزونه‌ی وردپرس می‌گوید «رمز اتصال درست نیست» | رمز اتصال را دوباره از صفحه‌ی شرکت کپی کنید |
| به‌روزرسانی زنده (نقطه‌ی سبز بالای منو) قطع است | پروکسی جلوی سرور اتصال‌های طولانی را می‌بندد؛ با Caddy همین فایل کار می‌کند |
| سرور بالا نمی‌آید و در لاگ `Invalid configuration` است | نام متغیر اشتباه در همان پیام آمده؛ `.env` را درست کنید (مثلاً APP_SECRET دست‌کم ۳۲ نویسه) |
| در لاگ `Migration … changed after it was applied` | فایل‌های برنامه دست‌کاری شده‌اند؛ نسخه‌ی رسمی را دوباره بگیرید (`git checkout .`) |
